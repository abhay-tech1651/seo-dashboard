Abhay rejected the Streamlit and the React/Recharts dashboards (6 Nov 2026): "looks cheap", "not at all understandable", "just putting graphs is not good", "you're only talking about Ivory". He liked the County Search Ads Handbook artifact (Instrument Sans + JetBrains Mono, green accent, contents rail, ledger cards, plain-language sections) better than any dashboard.

Update 7 Nov: he then rejected the Google Sheets + Apps Script web app too (confusing setup, opens in some browsers and not others) and asked for a modern React/Next.js + Node dashboard "worthy of Opus on ultracode". Manual daily steps are fine with him; perfect data is non-negotiable. Keep explanations to him short and plain; he gets confused by long multi-step instructions.

**Why:** He presents to a senior manager and to beginners; the tool must read like a briefing a layman understands and show expertise, not a page of charts. Every project (Ivory, Clove, Cocoa, Jade) must get the same depth.

**How to apply:** Build data products in the handbook's visual language: a one-paragraph lede with the numbers in sentences, a short "in one minute" list, one card per project with the same structure, problems grouped by who fixes them (Agency / County / Google CTM team), compact tables with "show all", few charts and each with a "how to read it" caption. Prefer Google Sheets + Apps Script as the home for County tools (his suggestion; data stays in Google, works on his Mac and phone, shareable with the boss).
